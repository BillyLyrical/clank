## 1. BIN/CLANKD — NDJSON Protocol Testing
================================================================================

### 1.1 Startup / Shutdown

- `clankd --provider=mock --stdio` starts without error, session_id returned
- `clankd --help` prints usage, exits 0
- Invalid options: `clankd --bogus` prints usage, exits 2
- EOF on stdin exits cleanly (no zombies) — verify with `pgrep -f clankd`
- `clankd --provider=mock --db=_test/clankd_test.db` — explicit DB path
- `clankd --provider=mock --db=:memory:` — ephemeral DB (default behavior)

### 1.2 Protocol Commands

Ping/pong:
  -> {"id":1,"command":"ping"}
  <- {"id":1,"ok":1,"pong":1}
  PASS: response contains ok=1 and pong=1

Session info:
  -> {"id":1,"command":"session_info"}
  <- {"id":1,"ok":1,"session_id":"...","messages":N,...}
  PASS: session_id is non-empty string, messages is integer

Status:
  -> {"id":1,"command":"status"}
  <- {"id":1,"ok":1,"pid":12345,"session_id":"...","daemon":0}
  PASS: pid matches PID of clankd process

Tools:
  -> {"id":1,"command":"tools"}
  <- {"id":1,"ok":1,"tools":[...],"wits":[...],"skipped":[...]}
  PASS: tools is arrayref, wits is arrayref

Shutdown:
  -> {"id":1,"command":"shutdown"}
  <- {"id":1,"ok":1,"bye":1}
  PASS: process exits 0, no orphan processes

Restart (resume same session):
  Start clankd --provider=mock --db=_test/restart_test.db
  -> {"id":1,"prompt":"first turn"}
  -> {"id":2,"command":"restart"}
  <- {"id":2,"ok":1,"session_id":"...","resumed":1}
  -> {"id":3,"prompt":"second turn"}
  -> {"id":4,"command":"session_info"}
  <- {"id":4,"ok":1,"messages":6,...}
  PASS: session_id same as original, messages include both turns
  PASS: resumed=1 indicates session was resumed

Restart (fresh session):
  -> {"id":1,"prompt":"turn 1"}
  -> {"id":2,"command":"restart","fresh":true}
  <- {"id":2,"ok":1,"session_id":"...","resumed":0}
  -> {"id":3,"prompt":"turn 2"}
  -> {"id":4,"command":"session_info"}
  <- {"id":4,"ok":1,"messages":4,...}
  PASS: new session_id (different from original)
  PASS: resumed=0 indicates fresh start
  PASS: turn 2 history is clean (no turn 1)

Unknown command:
  -> {"id":1,"command":"bogus"}
  <- {"id":1,"ok":0,"error":"unknown command 'bogus'"}
  PASS: ok=0, error field present

Missing command:
  -> {"id":1}
  <- {"id":1,"ok":0,"error":"unknown or missing command"}
  PASS: graceful rejection

Invalid JSON:
  <- not-json
  <- {"ok":0,"error":"invalid JSON"}
  PASS: no crash, error returned

### 1.3 Prompt Handling

Empty prompt:
  -> {"id":1,"prompt":""}

Missing prompt:
  -> {"id":1,"command":"prompt"}

Prompt with timeout:
  -> {"id":1,"prompt":"hello","timeout":10}
  <- {"id":1,"ok":1,...}
  PASS: respects timeout, returns within 10s

### 1.5 Socket Transport

Start with `clankd --provider=mock --socket=_tmp/clankd_test.sock`
  - Connect via `socat` or perl IO::Socket::UNIX
  - Send JSON line, receive JSON response
  - Disconnect and reconnect — session persists
  - Send shutdown — process exits, socket cleaned up
  - Verify: `ls _tmp/clankd_test.sock` should not exist after shutdown

### 1.6 Daemon Mode

Start with `clankd --provider=mock --socket=_tmp/clankd_daemon.sock --daemon`
  - `clankd --status` returns ok=1, running=1, pid=N
  - Verify process exists: `kill -0 $pid`
  - `clankd --stop` sends TERM, process exits
  - `clankd --status` returns ok=0, no running daemon
  - Verify PID file cleaned up: `! -f ~/.clank/clankd.pid`

### 1.7 Concurrent Clients (Socket)

Start daemon, connect two clients simultaneously:
  - Client A sends prompt
  - Client B sends prompt
  - Both get correct responses (no cross-contamination)
  - Disconnect one — other continues working

## 2. REPL — Interactive Interface Testing
================================================================================

### 2.1 Startup

- `bin/clank --provider=mock` starts, prints banner
- Banner contains: version, provider name, DB path, session ID
- Banner lists loaded wits
- `type /help for commands` shown

### 2.2 Sigil Dispatch (Interactive)

Each sigil via direct REPL input:

  / — Command:
    `/help` — prints help text
    `/wits list` — lists wits
    `/compact` — runs compaction (if available)
    Unknown: `/bogus` — prints "unknown command"

  # — Comment:
    `# this is a comment` — no output, no side effects

  ? — Query:
    `? what is the meaning of life` — returns LLM response
    `?` (no args) — prints usage

  $ — Eval:
    `$ time()` — returns timestamp
    `$ use Clank::Util; uuid4()` — returns UUID
    `$ $store->kv_get('nonexistent')` — returns undef gracefully
    `$` (no args) — prints usage
    `$ this is not perl` — prints eval error (not crash)

  @ — Agent:
    `@list` or `@` — lists agent profiles
    `@status` — shows invocation stats
    `@reviewer summarize lib/Clank.pm` — spawns agent, returns output
    `@nonexistent do something` — prints error (profile not found)

  % — Pipeline:
    `% list` — lists available pipelines
    `% code-review` — runs named pipeline
    `% nonexistent` — prints "pipeline not found"

  > — Pipe:
    `> summarize this text | classify | critique` — runs inline pipeline
    `>` (no args) — prints usage

  : — Topic:
    `: test.topic` — publishes empty event
    `: listen tool_use` — listens for events on topic
    `: publish test.topic {"key":"value"}` — publishes with payload

  ~ — Wit:
    `~ list` — lists wits with state
    `~ load path/to/wit` — loads wit from directory
    `~ unload crit` — unloads wit by name
    `~ inspect critic` — shows wit details
    `~ status` — shows active/total counts

  ! — History:
    ! (after 3+ commands) — re-runs last command
    `! 1` — re-runs command #1
    `! -2` — re-runs 2 commands ago
    `! last` — re-runs last command
    ! (no history) — prints "(no history yet)"

### 2.3 Bare Text (LLM Fallback)

### 2.4 History

### 2.6 Streaming

## 3. CLANK::SIGIL — Shared Dispatch Library
================================================================================

### 3.1 Unit Tests (t/52_sigil.t)

- new() creates dispatcher with empty handlers
- register() adds handler, returns self (chainable)
- dispatch() with registered sigil calls handler
- dispatch() with unregistered sigil returns undef (fall-through)
- dispatch() with undef/empty line returns undef
- dispatch() strips leading whitespace after sigil
- dispatch() catches handler errors, returns error output
- is_command() returns 1 for registered sigil, 0 otherwise
- is_command() returns 0 for undef/empty

### 3.2 Integration: REPL vs clankd

- Same input produces same handler in both REPL and clankd
- REPL handler has access to $app (full harness)
- clankd handler has access to $driver (NDJSON protocol)
- Both share the same Sigil.pm dispatch logic
- Test: register handler in Sigil, dispatch in both contexts, verify output matches

## 4. CLANK::PIPELINE — Parser and Runner
================================================================================

### 4.1 Parser Unit Tests (t/53_pipeline.t)

Basic blocks:
  - Pipeline[ name("test") ] — extracts name
  - Pipeline[ name("test") about("desc") version("1") ] — extracts all props
  - Source[ name("src") topic("input") ] — categorized as source
  - Agent[ name("a1") wit("git") tool("blame") subscribe("input") publish("output") ] — full agent block
  - Sink[ name("sink") subscribe("output") topic("done") ] — categorized as sink

Properties:
  - name("value") — sets name
  - subscribe("topic1") subscribe("topic2") — collects into arrayref
  - wit("logic") — sets wit
  - tool("critique") — sets tool
  - publish("topic") — sets publish topic

Comments:
  - `# this is a comment` — stripped
  - `name("test") # inline comment` — comment stripped, prop parsed
  - `name("has # inside")` — # inside quotes preserved (critical fix)

Edge cases:
  - Empty text — returns empty pipeline
  - Whitespace-only lines — skipped
  - Unclosed block — last block still collected

### 4.2 Blueprint Loading

- Pipeline->list() returns sorted .clank files from pipeline_dir
- Pipeline->load("name") reads name.clank, parses, returns hashref
- Pipeline->load("nonexistent") returns undef
- pipeline_dir defaults to ~/.clank/pipelines, overridable

### 4.3 Blueprint Files (test artifacts in _test/pipelines/)

Create test blueprints in _test/pipelines/:

  simple.clank:
    Pipeline[ name("simple") about("simple test pipeline") ]
    Source[ name("src") topic("test.input") ]
    Agent[ name("echo") wit("psh") tool("eval") subscribe("test.input") publish("test.output") ]
    Sink[ name("out") subscribe("test.output") topic("test.done") ]

  fork.clank:
    Pipeline[ name("fork") about("fan-out test") ]
    Source[ name("src") topic("fork.input") ]
    Agent[ name("a1") wit("psh") tool("eval") subscribe("fork.input") publish("fork.a1") ]
    Agent[ name("a2") wit("psh") tool("eval") subscribe("fork.input") publish("fork.a2") ]
    Sink[ name("out") subscribe("fork.a1") subscribe("fork.a2") topic("fork.done") ]

  merge.clank:
    Pipeline[ name("merge") about("fan-in test") ]
    Source[ name("src") topic("merge.input") ]
    Agent[ name="split" wit="psh" tool="eval" subscribe="merge.input" publish="merge.split" ]
    Agent[ name="process" wit="psh" tool="eval" subscribe="merge.split" publish="merge.done" ]
    Sink[ name="out" subscribe="merge.done" topic="merge.result" ]

### 4.4 Pipeline Execution

  - Wire sinks before sources (order matters)
  - Sources publish to bus, agents process, sinks collect
  - Bus delivers events to correct subscribers
  - After run, all subscriptions cleaned up (no leaks)

### 4.5 Inline Pipes (> stage1 | stage2 | stage3)

- Single stage: `> summarize` — passes through
- Two stages: `> summarize | classify` — output of first feeds second
- Three stages: `> summarize | classify | critique` — chain works
- Empty input: stages receive empty string
- Stage error: returns error message, doesn't crash
- Whitespace around pipes: `> a | b ` — trimmed correctly

### 5.2 Clank::Agent Module (lib/Clank/Agent.pm)

  Agent->list — returns sorted list of profile names
  Agent->load("reviewer") — returns {name, description, tools, model, max_turns, prompt}
  Agent->load("nonexistent") — returns undef or dies

  Agent->route("scan for SQL injection") — matches security agent
  Agent->route("review this code") — matches reviewer agent
  Agent->route("fix the bug") — matches debugger agent
  Agent->route("design the architecture") — matches architect agent
  Route scoring > 0.1 threshold required

  Agent->spawn(name=>"reviewer", prompt=>"read lib/Clank.pm", loop=>$loop)
    — creates child session with tool filter
    — only reviewer's allowed tools visible to LLM
    — returns {ok, output, session_id, turns}
    — bus events: pre_agent_start, subagent_start, subagent_stop, agent_end

  Agent->stats — returns {reviewer => {calls, ok, errors, turns}, ...}
  Stats increment after each spawn

  Agent->comply(name=>"reviewer", prompt=>"read file", loop=>$loop)
    — records tool_use events
    — compares against allowlist
    — returns {compliant, allowed_tools, used_tools, violations}

### 5.3 Tool Allowlist Enforcement

  - Spawn reviewer: only read, bash visible (no edit, no write)
  - LLM attempts to use disallowed tool → tool not in schema
  - Verify: LLM never sees tools outside allowlist
  - Verify: tool filter applied at Session level, not Loop level

## 8. REGRESSION / EDGE CASES
================================================================================

### 8.1 Error Handling

  - clankd: malformed JSON → error response, no crash
  - clankd: unknown command → error response
  - REPL: eval of invalid Perl → eval error message
  - REPL: agent spawn with nonexistent profile → error
  - Pipeline: missing blueprint → "not found" message
  - Pipeline: broken blueprint → parse error, no crash

### 8.2 State Management

  - clankd session persists across multiple prompts
  - --resume restores previous session
  - restart command resumes same session (preserves history)
  - restart with fresh=true creates new session (clean history)
  - /new creates fresh session (old state preserved)
  - Store DB is consistent after normal operation

### 8.3 Concurrency

  - Socket mode: multiple clients can connect
  - Each client gets independent responses
  - No cross-client state leakage

### 8.4 Resource Cleanup

  - Socket file removed on shutdown
  - PID file removed on daemon shutdown
  - Bus subscriptions cleaned after pipeline run
  - No zombie processes after stdio EOF
