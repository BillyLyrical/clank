# Context Engineering for Clank

Status: implemented. How Clank assembles context for the LLM, the five
pipelines that compose it, and how to extend them.

---

## 1. The Problem

When an agent has hundreds of tools, dumping every schema into the system
prompt fails:

- **Token cost**: 500 tools × ~100 tokens = 50k tokens burned before the
  user speaks.
- **Selection degradation**: LLMs struggle to pick the right tool past ~50.
- **Context pollution**: Tool schemas crowd out history and reasoning.

Clank solves this with five context pipelines that compose into a single
system prompt before each LLM call. Total cost: ~5-8k tokens instead of 50k.

---

## 2. The Five Pipelines

Before each LLM call, Loop.pm assembles context in this order:

```
┌─────────────────────────────────────────────────────┐
│  1. CAPABILITY CONTEXT (what can I do?)             │
│     PluginManager::manifest() → system prompt        │
│     ToolSelector → relevant tool schemas (RATS)     │
├─────────────────────────────────────────────────────┤
│  2. BEHAVIORAL CONTEXT (how should I act?)          │
│     ContextRules → deterministic DSL injections     │
├─────────────────────────────────────────────────────┤
│  3. KNOWLEDGE CONTEXT (what do I know?)             │
│     bus: context.knowledge_request                  │
│       ├── WorldModel → entities, facts, beliefs     │
│       └── Crystallizer → deterministic rules        │
├─────────────────────────────────────────────────────┤
│  4. CONTEXT COMPRESSION                             │
│     Post-tool-call summarization (large outputs)    │
│     Context-aware pruning (old unreferenced turns)  │
├─────────────────────────────────────────────────────┤
│  5. CONVERSATION HISTORY                            │
│     Recent messages + current user prompt            │
└─────────────────────────────────────────────────────┘
```

---

## 3. Pipeline 1: Capability Context

**What it does**: Tells the LLM what tools exist without dumping all schemas.

### 3.1 The Capability Manifest

Generated by `PluginManager::manifest()` after wits are loaded. Always
injected into the system prompt. Cost: ~500 tokens.

```
CAPABILITIES (125 wits, 10 decks):
  critic  style, security, quality, accessibility, ethics, performance, ...
  db      connect, query, execute, schema, shell, history, export, import
  fs      read, write, edit, delete, copy, move, mkdir, search, test, ...
  git     status, commit, stash, grep, bisect, diff, ignore, blame, ...
  logic   axiom, deduce, given, rule, apply, contrapositive, certainty, ...
  neuro   neurointegration, crystallizer, constraints
  perl    syntax, test, doc, testgen, dump, trace, podread, deps, ...
  psh     eval, help, vars
  search  search, local, kagi, duckduckgo, yandex, llm, bing, brave, google
```

The manifest is derived from what's *actually loaded*, not what *could be
loaded*. It updates when wits are loaded/unloaded.

### 3.2 RATS: Retrieval-Augmented Tool Selection

When the number of tools exceeds `max_tools`, `ToolSelector::select()`
scores them by relevance and returns only the top N.

**Base scoring**: keyword overlap between tool hints/descriptions and the
prompt (TF-based).

**Context signals** (additive boosts):

| Signal | Boost | Source |
|--------|-------|--------|
| `recent_tools` | +0.3 | Tools used in recent turns (event journal) |
| `loaded_wits` | +0.2 | Tools from currently loaded decks (manifest) |
| `file_types` | +0.15 | Tools matching file types in recent messages |
| `error_msg` | +0.25×matches | Tools whose hints match error words |

```perl
# Loop.pm builds context automatically:
my $selected = Clank::ToolSelector->select(
    tools   => \@all_tools,
    prompt  => $last_msg,
    max     => $self->{max_tools},
    context => $ctx,    # { recent_tools, loaded_wits, file_types, error_msg }
);
```

## 4. Pipeline 2: Behavioral Context

**What it does**: Injects rules and constraints based on the current task.
Deterministic — no LLM call needed.

Powered by `Clank::ContextRules`, which evaluates DSL rules against the
prompt and returns injection text.

### 4.1 How It Works

```
Prompt → regex match → rule fires → injection text → system prompt
```

### 4.2 Default Rules

| Rule | Trigger | Injection |
|------|---------|-----------|
| `inject_perl_style` | `edit *.pm/*.pl/*.t` | "Always use strict and warnings..." |
| `inject_perl_modern` | `edit *.pm` | "Use modern Perl features..." |
| `inject_db_context` | `database/query/sql/...` | "Database tools available: db_connect..." |
| `inject_git_context` | `git/commit/branch/...` | "Git tools available: git_status..." |
| `inject_test_context` | `test/spec/prove/...` | "Test tools: perl_syntax, perl_test..." |
| `inject_logic_context` | `datalog/logic/prove/...` | "Logic tools: datalog_query..." |
| `inject_security` | `security/vulnerability/...` | "Never log secrets, validate input..." |
| `inject_conciseness` | `concise/brief/short/...` | "Be concise. Minimize output tokens." |
| `inject_no_comments` | `no comment/without comment` | "Do NOT add comments..." |

### 4.3 Adding Custom Rules

Extend via the DSL:

```perl
my $cr = Clank::ContextRules->new(dsl => <<'DSL');
rule inject_my_team_style priority 10
    when /(?:myteam|our.?project)/i
    then inject Follow team style guide: 4-space indent, no heredocs.
end
DSL
```

Or register rules at runtime:

```perl
$bus->publish('context.knowledge_request', { prompt => $prompt });
```

## 5. Pipeline 3: Knowledge Context

**What it does**: Retrieves relevant facts from the world model and
crystallized rules. Wired via bus events.

### 5.1 Bus Flow

```
Loop.pm publishes:  context.knowledge_request { prompt }
                        │
    ┌───────────────────┼───────────────────┐
    ▼                   ▼                   ▼
WorldModel          Crystallizer        (future: Store)
{ facts: [...] }    { rules: [...] }
    │                   │
    └─────────┬─────────┘
              ▼
    Loop collects → injects as [knowledge context] message
```

### 5.2 WorldModel Response

Queries FTS5-indexed entities, facts, and beliefs matching the prompt:

```perl
$bus->subscribe('context.knowledge_request', sub {
    my ($ev) = @_;
    my $prompt = $ev->{payload}{prompt};
    # Returns: { facts => [{ type => 'entity'|'fact'|'belief', text => '...' }] }
});
```

### 5.3 Crystallizer Response

Returns deterministic rules whose names or conditions match the prompt:

```perl
# Returns: { rules => [{ type => 'crystallized_rule', text => '...' }] }
```

### 5.4 Extension Points

Subscribe to `context.knowledge_request` to add your own knowledge sources:

```perl
$api->on('context.knowledge_request', sub {
    my ($ev) = @_;
    my $prompt = $ev->{payload}{prompt};
    # Query your data source...
    return { facts => [{ type => 'custom', text => '...' }] };
});
```

## 6. Context Compression

Two mechanisms keep context manageable in long sessions.

### 6.1 Post-Tool-Call Summarization

After a tool executes, if its output exceeds ~1000 tokens (4000 chars),
Loop.pm summarizes it via the LLM before adding to the conversation:

```
Tool output (5000 tokens) → LLM summary (200 tokens) → session
```

The summary preserves key results, errors, file paths, and line numbers.
Falls back to the original output on failure.

### 6.2 Context-Aware Pruning

`Messages::prune_context()` drops unreferenced old turns:

- **Keeps**: Last 20 turns, all compaction entries, tool results referenced
  by recent messages.
- **Drops**: Old user/assistant turns not referenced by anything recent.

Applied automatically when the message chain exceeds 24 entries.

### 6.3 Threshold Compaction

Pi-semantics compaction (existing): when `est_tokens(context) > context_window - reserve`,
summarizes the older span into a structured summary via the LLM.

```perl
# Triggered automatically between turns.
if ($self->{compactor}->should_compact($est)) {
    $self->{compactor}->compact(
        store => $session->store, session_id => $session->id,
        provider => $session->provider, bus => $bus,
    );
}
```

## 7. The Assembly Sequence in Code

Here's what happens in `Loop.pm::run_prompt()` before each provider call:

```perl
# 1) Build base context from session messages.
my $msgs = $session->build_context;

# 2) Bus hook: wits can modify messages.
my $cx = $bus->publish('context', { messages => $msgs, system_prompt => $sp });

# 3a) Prune old unreferenced turns.
if (@$msgs > 24) {
    my $pruned = Clank::Session::Messages::prune_context($msgs, keep_recent => 20);
    $msgs = $pruned if $pruned != $msgs;
}

# 3b) Deterministic context rules (DSL → injection).
my $rule_text = $context_rules->format_for_prompt(prompt => $sp);
$sp .= "\n\n$rule_text" if $rule_text;

# 3c) Knowledge context (bus → world model + crystallizer).
my $kr = $bus->publish('context.knowledge_request', { prompt => $last_msg });
# Collect facts + rules, inject as [knowledge context] message.

# 4) RATS: select relevant tools.
my $selected = Clank::ToolSelector->select(
    tools => \@all_tools, prompt => $last_msg,
    max => $self->{max_tools}, context => $ctx,
);

# 5) Provider call.
my $payload = $provider->chat_payload(
    messages => [ { role => 'system', content => $sp }, @$msgs ],
    tools    => \@schemas,
);
```

## 8. Token Budget

| Component | Tokens | When |
|-----------|--------|------|
| Core tools (read, bash, edit, write) | ~200 | Always |
| Capability manifest | ~500 | Always |
| Behavioral rules | ~200-800 | When rules match |
| Knowledge context | ~200-1000 | When facts exist |
| Conversation history | variable | Recent 20 turns |
| **Total system prompt** | **~5-8k** | **vs. 50k naive** |

Cost per call (GPT-4o): ~$0.015-0.03 vs. ~$0.15 naive.

## 9. Module Reference

| Module | Pipeline | Purpose |
|--------|----------|---------|
| `PluginManager::manifest()` | Capability | Generates deck-level capability string |
| `ToolSelector::select()` | Capability | RATS: scores tools by relevance + context |
| `ContextRules` | Behavioral | DSL rules → injection text |
| `WorldModel::register()` | Knowledge | Responds to `context.knowledge_request` |
| `Crystallizer::register()` | Knowledge | Responds with crystallized rules |
| `Messages::prune_context()` | Compression | Drops unreferenced old turns |
| `Loop::_summarize_tool_output()` | Compression | Summarizes large tool outputs |
| `Session::Compaction` | Compression | Threshold-based conversation compaction |

## 10. Extending the System

### Add a Context Rule

```perl
# In a wit's register():
$api->on('context.knowledge_request', sub {
    my ($ev) = @_;
    return { facts => [{ type => 'wit_fact', text => '...' }] };
});
```

### Add a Behavioral Rule

```perl
my $cr = Clank::ContextRules->new(dsl => <<'DSL');
rule my_rule priority 10
    when /pattern/i
    then inject "Your injection text here"
end
DSL
```

### Override Tool Selection

```perl
$api->on('before_provider_request', sub {
    my ($ev) = @_;
    # Modify tools in $ev->{payload}{tools}
    return { payload => $ev->{payload} };
});
```

### Add a Knowledge Source

Subscribe to `context.knowledge_request` and return `{ facts => [...] }`.
Loop.pm collects all responses and injects them as a knowledge context
message.
